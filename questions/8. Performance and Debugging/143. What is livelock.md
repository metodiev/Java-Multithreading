# 143. What is a livelock?

> **Section:** Performance and Debugging · **Related:** [144. Livelock versus deadlock](144.%20Livelock%20versus%20deadlock.md)

## TL;DR

In a livelock, threads remain active and react to each other but repeatedly fail to make useful progress.

## Example

Two workers detect a conflict, both back off, then retry simultaneously and conflict again. Unlike a deadlock, they are not necessarily blocked; CPU may remain busy while completed business work stays flat.

```mermaid
sequenceDiagram
    participant A as Worker A
    participant B as Worker B
    A->>B: Detect conflict; back off
    B->>A: Detect conflict; back off
    A->>B: Retry together
    B->>A: Retry together
    Note over A,B: Repeated activity, no progress
```

## Practical insight

Compare retry counts and useful completion metrics with CPU profiles and repeated stack samples. Randomized or asymmetric backoff, a clear owner, or a bounded retry policy can break synchronized retry patterns.

**Pitfall:** Adding more threads can intensify a livelock if they all follow the same retry schedule.
