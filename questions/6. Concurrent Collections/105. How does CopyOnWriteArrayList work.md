# 105. How does CopyOnWriteArrayList work?

> **Section:** 6. Concurrent Collections · **Level:** Practitioner to architect

## TL;DR

A mutation copies and safely publishes a new array; iterators retain their original snapshot.

## How it works

Mutations create and publish a new backing array; readers access a stable snapshot without locking. Iterators retain the array snapshot from iterator creation and do not observe later changes. A write-heavy workload pays copying and allocation costs proportional to list size.

## Example

```java
CopyOnWriteArrayList<String> listeners = new CopyOnWriteArrayList<>();
```

## Mermaid diagram

```mermaid
flowchart LR
    A[Writer copies array] --> B[Published array]
    B --> C[Snapshot reader]
```

## Architect insight

Snapshot iteration simplifies listener notification but trades off write amplification.

## Common pitfall

Frequent writes copy the array and create allocation and GC pressure.
