# 113. When to prefer synchronized collections?

> **Section:** 6. Concurrent Collections · **Level:** Practitioner to architect

## TL;DR

A synchronized wrapper fits low contention or a compound invariant governed by one monitor.

## How it works

Prefer a synchronized wrapper for small, low-contention legacy structures or when a single lock must protect a compound invariant across operations. Synchronize the entire iteration and every related access on the wrapper. For contention or independent concurrent updates, use a concurrent collection instead.

## Example

```java
synchronized (map) { for (Map.Entry<K, V> e : map.entrySet()) consume(e); }
```

## Mermaid diagram

```mermaid
flowchart LR
    A[Shared monitor] --> B[Compound invariant]
    B --> C[Protected traversal]
```

## Architect insight

A single lock may be simpler when every related access follows the same protocol.

## Common pitfall

Protect the entire iteration, not only iterator creation.
