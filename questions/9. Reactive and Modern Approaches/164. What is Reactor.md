# 164. What is Reactor?

> **Section:** Reactive and Modern Approaches · **Related:** [176. How does backpressure work in Reactor](176.%20How%20does%20backpressure%20work%20in%20Reactor.md)

## TL;DR

Project Reactor is a JVM reactive library built around `Mono` (zero or one value) and `Flux` (zero to many values), with operators, schedulers, cancellation, and Reactive Streams demand.

```java
Flux<Integer> ids = Flux.range(1, 3)
        .map(id -> id * 10);
```

Pipelines are generally lazy: work starts on subscription. In a Spring reactive application, avoid blocking event-loop threads. Use truly asynchronous clients where possible; isolate unavoidable blocking work on a bounded scheduler.

```mermaid
flowchart LR
    S[Subscribe] --> P[Publisher pipeline]
    P -->|demand / values| O[Operators]
    O --> D[Subscriber]
    D -->|cancel| P
```

## Practical insight

Backpressure and scheduler choice are separate concerns: demand regulates elements, while a scheduler controls execution. Neither automatically limits database connections.

**Pitfall:** Constructing a `Mono` or `Flux` alone does not usually execute the pipeline.
