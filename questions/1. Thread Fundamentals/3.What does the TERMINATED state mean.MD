# 3. What does the TERMINATED state mean?

> **Section:** Thread Fundamentals · **Level:** Architect / Tech Lead · **Related code:** `src/com/java/multithreading/interview/questions/ThreadLifecycleDemo.java`

## TL;DR

`TERMINATED` means the thread's `run()` method has returned — either normally or after an uncaught exception propagated out of it. The thread is dead and **cannot be restarted**. Its native resources are released, but the `Thread` object remains as a normal heap object you can still query (`getState()` returns `TERMINATED`, `isAlive()` returns `false`).

## Deep Dive

### How a thread reaches TERMINATED

- `run()` completes and returns.
- `run()` throws an exception that is not caught. The exception is routed to the thread's `UncaughtExceptionHandler`, then the thread dies.

### What "dead" means

| Property | Value after termination |
| --- | --- |
| `isAlive()` | `false` |
| `getState()` | `TERMINATED` |
| `start()` again | `IllegalThreadStateException` |
| Stack / native resources | Released |
| Object on heap | Still referenced until GC |

## Diagram

```mermaid
flowchart TD
    A[run() executing] --> B{Exception thrown?}
    B -- No --> C[run returns normally]
    B -- Yes --> D[UncaughtExceptionHandler runs]
    C --> E[TERMINATED]
    D --> E
    E --> F[isAlive = false]
    E --> G[Resources released]
    E --> H[start() again -> IllegalThreadStateException]
```

## Code Walkthrough

```java
// src/com/java/multithreading/interview/questions/ThreadLifecycleDemo.java
t.start();
t.join();                                            // wait for death
System.out.println(t.getState());                    // TERMINATED
```

- `join()` blocks until the worker reaches `TERMINATED`.
- After that, the object is inert but still inspectable.

## Architect / Tech-Lead Insights

- A thread that dies from an uncaught exception silently disappears from a pool unless you set an `UncaughtExceptionHandler` (or use the pool's `ThreadFactory`). This is a classic "the task just stopped" production mystery.
- Don't use `Thread` liveness as a health check for pooled executors — track task completion (`Future`, `CountDownLatch`) instead.
- Terminated threads that you keep referencing (e.g. in a `List<Thread>`) leak memory if you never clear the list.

## Common Pitfalls

| Pitfall | Why it hurts | Fix |
| --- | --- | --- |
| Assuming the task "succeeded" | Uncaught exceptions also end in TERMINATED | Set an uncaught-exception handler / inspect `Future` |
| Calling `start()` again | Throws `IllegalThreadStateException` | Create a new thread/task |
| Holding thread references forever | Memory leak | Clear references, use weak refs |

## Interview Q&A

**Q:** Does TERMINATED imply success?
**A:** No — an uncaught exception also terminates the thread.

**Q:** Can a terminated thread be reused?
**A:** Never. You must create a new `Thread` or resubmit a `Runnable`/`Callable`.
