# 7. How do you create a daemon thread?

> **Section:** Thread Fundamentals · **Level:** Architect / Tech Lead · **Related code:** `src/com/java/javathread/ThreadExample9.java`, `ThreadExample10.java`, `src/com/java/multithreading/interview/questions/DaemonExample.java`

## TL;DR

Create the thread as usual, then call `thread.setDaemon(true)` **before** calling `start()`. The flag is inherited by any child threads created by that thread. Calling `setDaemon()` after the thread has started throws `IllegalThreadStateException`.

## Deep Dive

### The recipe

```java
Thread t = new Thread(task, "bg-monitor");
t.setDaemon(true);   // BEFORE start()
t.start();
```

### Rules of thumb

| Rule | Detail |
| --- | --- |
| Timing | Must be set before `start()` |
| Inheritance | Child threads inherit the daemon flag |
| Default | New threads inherit the creating thread's flag |
| Executors | Provide a custom `ThreadFactory` to make pool threads daemon |

### Making a pool daemon

```java
ThreadFactory daemonFactory = r -> {
    Thread t = new Thread(r);
    t.setDaemon(true);
    return t;
};
ExecutorService pool = Executors.newFixedThreadPool(4, daemonFactory);
```

## Code Walkthrough

`ThreadExample9` creates an infinite daemon and lets `main` end:

```java
// src/com/java/javathread/ThreadExample9.java
Runnable runnable = () -> {
    while (true) {
        sleep(1000);
        System.out.println("Running");
    }
};
Thread thread = new Thread(runnable);
thread.setDaemon(true);
thread.start();
sleep(3100);                    // main exits -> daemon dies
```

`ThreadExample9` now follows the required order. `ThreadExample10` also sets the flag before starting and then `join()`s — which keeps `main` alive until the daemon completes 5 iterations:

```java
// src/com/java/javathread/ThreadExample10.java
Thread thread = new Thread(runnable);
thread.setDaemon(true);   // correct order
thread.start();
thread.join();            // main waits, so the daemon actually finishes
```

> `setDaemon()` must be called before `start()`; calling it after the thread has started throws `IllegalThreadStateException`.

## Architect / Tech-Lead Insights

- Daemon + `join()` is a useful trick: the thread is cheap to abandon, yet you can still wait for it when you *do* need the result.
- Never daemonise a thread that performs durable I/O; it can be killed mid-write.
- Logging frameworks and monitoring agents often use daemon threads internally — this is why your app can exit "cleanly" even with them running.

## Common Pitfalls

| Pitfall | Why it hurts | Fix |
| --- | --- | --- |
| `setDaemon` after `start` | `IllegalThreadStateException` | Set before `start()` |
| Daemonising critical work | Silent data loss on exit | Keep it a user thread |
| Assuming pool threads are daemon | They aren't by default | Custom `ThreadFactory` |

## Interview Q&A

**Q:** Can a daemon thread create a non-daemon child?
**A:** Not by default — children inherit the parent's daemon flag; you must explicitly change it.

**Q:** How do you make an `ExecutorService` daemon?
**A:** Pass a `ThreadFactory` that calls `setDaemon(true)`.
