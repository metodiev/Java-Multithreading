# 39. What are lock contention and its effects?

> Section: Synchronization and Locks · Java 8 baseline · [Section guide](README.md)

## Answer and deep dive

Lock contention occurs when threads frequently compete for the same lock and must queue or retry. It can limit throughput, increase tail latency and context switches, and leave cores idle while work is serialized.

Diagnose with thread dumps and lock profiling before changing the design. Typical remedies include shortening critical sections, avoiding blocking I/O while holding locks, reducing shared mutable state, or using a concurrent data structure when it matches the invariant.

## Mermaid: contention bottleneck

```mermaid
flowchart LR
    A[Many worker threads] --> Q[Queue for one lock]
    Q --> C[Serialized critical section]
    C --> O[Reduced throughput and higher latency]
    O --> D[Profile and identify protected work]
    D --> R[Reduce sharing or lock hold time]
```

## Pitfall / architect insight

Finer-grained locks are not automatically faster: they add coordination complexity and can introduce lock-order deadlocks. Change one measured bottleneck at a time and revalidate the invariant.
