# 33. How do you use await() and signal() with conditions?

> Section: Synchronization and Locks · Java 8 baseline · [Section guide](README.md)

## Answer and deep dive

Guard the shared predicate with the condition's lock, wait in a `while` loop, update the predicate before signalling, and unlock in `finally`. `signal()` wakes one waiter; `signalAll()` wakes all waiters, which must then compete to reacquire the lock.

```java
lock.lock();
try {
    while (!ready) {
        readyCondition.await();
    }
    consume();
} finally {
    lock.unlock();
}
```

The producer should acquire the same lock, set `ready = true`, and then signal. If `await()` is interrupted, it reacquires the lock before throwing, so the `finally` still releases it.

## Mermaid: predicate protocol

```mermaid
sequenceDiagram
    participant C as Consumer
    participant L as Lock and Condition
    participant P as Producer
    C->>L: lock; test predicate
    C->>L: await (release lock)
    P->>L: lock; update predicate
    P->>L: signal
    P->>L: unlock
    C->>L: reacquire; retest predicate
```

## Pitfall / architect insight

Calling `signal()` before changing the guarded state can wake a thread that still finds the predicate false. Keep predicate transition and notification in one locked protocol.
