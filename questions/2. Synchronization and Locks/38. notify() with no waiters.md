# 38. What happens if notify() is called with no waiting threads?

> Section: Synchronization and Locks · Java 8 baseline · [Section guide](README.md)

## Answer and deep dive

If an object's wait set is empty, `notify()` (or `notifyAll()`) has no effect. Notifications are not queued for future waiters. A correct protocol stores the event or availability as state, updates it under the same monitor, and checks the state before waiting.

```java
synchronized (lock) {
    while (!ready) {
        lock.wait();
    }
    consume();
}
```

The producer sets `ready = true` while holding `lock` and then notifies. A thread arriving later sees the predicate and does not wait, even though the earlier notification was lost.

## Mermaid: state persists, notification does not

```mermaid
sequenceDiagram
    participant P as Producer
    participant M as Shared monitor/state
    participant C as Later consumer
    P->>M: set ready = true
    P->>M: notify with no waiters (not stored)
    C->>M: acquire and test ready
    M-->>C: ready is true; proceed
```

## Pitfall / architect insight

Do not build correctness around notification timing. Use a predicate, queue, semaphore, latch, or another stateful coordination utility appropriate to the event semantics.
