# 137. How does batching improve concurrency efficiency?

> **Section:** 7. Concurrency Patterns · **Level:** Practitioner to architect

## TL;DR

Batching amortizes per-item overhead but trades throughput for latency and memory.

## How it works

Batching amortizes per-item scheduling, I/O, locking, and protocol overhead and can improve throughput. It increases latency for early items, memory use, and retry blast radius. Use bounded batch sizes and maximum wait times, then tune using throughput and tail-latency measurements.

## Example

```java
if (shouldFlush(batch, deadline)) flush(batch);
```

## Mermaid diagram

```mermaid
flowchart LR
    A[Collect items] --> B[Count or time threshold]
    B --> C[Flush batch]
```

## Architect insight

Measure throughput and tail latency together; bound batch size and wait time.

## Common pitfall

Throughput-only benchmarks can hide unacceptable waiting and retry blast radius.
