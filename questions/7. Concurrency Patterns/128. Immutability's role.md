# 128. What role does immutability play in concurrency?

> **Section:** 7. Concurrency Patterns · **Level:** Practitioner to architect

## TL;DR

Immutable values are safe to share after construction because observable state cannot change.

## How it works

Immutable values can be safely shared after construction because their state cannot race with later mutation. They reduce the number of synchronization protocols and make message passing easier to reason about. Deep immutability matters: a final reference to a mutable collection does not make the collection immutable.

## Example

```java
record UserView(String name, List<String> roles) {} // copy roles defensively
```

## Mermaid diagram

## Architect insight

Use immutable boundary objects to clarify safe sharing and ownership.

## Common pitfall

Final references and records are only shallowly immutable if they expose mutable contents.
