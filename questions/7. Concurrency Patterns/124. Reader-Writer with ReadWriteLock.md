# 124. How is Reader-Writer implemented with ReadWriteLock?

> **Section:** 7. Concurrency Patterns · **Level:** Practitioner to architect

## TL;DR

Read with the shared lock and mutate with the exclusive lock; release both in finally.

## How it works

Guard reads with `readLock()` and mutations with `writeLock()`, using `try/finally` for each. Several readers coexist; a writer is exclusive. Do not attempt read-to-write upgrade while holding a read lock. For downgrade, acquire write, perform update, acquire read, then release write.

## Example

```java
lock.readLock().lock(); try { return state; } finally { lock.readLock().unlock(); }
```

## Mermaid diagram

```mermaid
flowchart LR
    A[Readers share lock] --> B[ReadWriteLock]
    B --> C[Writer exclusive lock]
```

## Architect insight

Encapsulate lock ownership so every access follows one protocol.

## Common pitfall

Do not try to upgrade while holding a read lock; it can deadlock.
