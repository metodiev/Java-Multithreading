# 134. What is the thread-per-message model?

> **Section:** 7. Concurrency Patterns · **Level:** Practitioner to architect

## TL;DR

Thread-per-message gives each request its own task; virtual threads can lower blocking-thread cost on supported JDKs.

## How it works

Each incoming message/request is handled by its own thread or task, making control flow straightforward and isolating blocking work. Platform threads are costly at very high concurrency; virtual threads can make this model more practical for blocking I/O. Still bound downstream resources and do not equate one thread with one CPU core.

## Example

```java
Thread.startVirtualThread(() -> handle(request));
```

## Mermaid diagram

```mermaid
flowchart LR
    A[Incoming message] --> B[Dedicated task]
    B --> C[Bounded downstream resource]
```

## Architect insight

Limit downstream resources even when task threads are cheap.

## Common pitfall

Virtual threads do not make databases or remote services infinitely concurrent.
