# 54. How does synchronization guarantee visibility?

> Section: Java Memory Model · Java 8 baseline · [Section guide](README.md)

## Answer and deep dive

Monitor release happens-before a later acquisition of the same monitor. A thread entering that synchronized region therefore sees writes that happened before the prior owner's release, as required by the JMM.

```java
// Both methods use the same monitor
synchronized void setValue(int value) { this.value = value; }
synchronized int getValue() { return value; }
```

This is a semantic guarantee, not a promise that the JVM literally flushes a particular CPU cache. The runtime may use barriers, cache-coherence operations, or other mechanisms appropriate to the platform.

## Mermaid: same-monitor edge

```mermaid
sequenceDiagram
    participant A as Thread A
    participant M as Monitor
    participant B as Thread B
    A->>M: acquire; write value
    A->>M: release
    B->>M: later acquire
    B->>B: read sees prior write
```

## Pitfall / architect insight

Every read and write participating in the shared invariant must follow the same synchronization discipline. Synchronizing only the writer does not protect unsynchronized readers.
