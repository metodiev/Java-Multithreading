# 42. How does synchronized establish happens-before?

> Section: Java Memory Model · Java 8 baseline · [Section guide](README.md)

## Answer and deep dive

An unlock of monitor M happens-before every subsequent lock of that same monitor. Therefore, writes performed before leaving a synchronized region become visible to a thread that later enters a synchronized region guarded by M.

```java
// Writer
synchronized (lock) {
    message = "ready";
}
// Reader
synchronized (lock) {
    System.out.println(message);
}
```

Both sides must use the identical lock object. Synchronizing on unrelated objects creates no corresponding edge, and a later unlock does not protect unsynchronized accesses by convention alone.

## Mermaid: monitor visibility edge

```mermaid
sequenceDiagram
    participant W as Writer
    participant M as Same monitor
    participant R as Reader
    W->>M: lock; write shared state
    W->>M: unlock
    M-->>R: later lock
    R->>R: read state; writer actions visible
```

## Pitfall / architect insight

Audit all accesses to the invariant: one unsynchronized reader can still observe a race. Lock identity and lock ordering should be explicit in code review.
