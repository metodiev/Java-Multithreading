# 92. What is the ABA problem in concurrency?

> **Section:** Atomic Operations and Lock-Free · **Java baseline:** 8 · [Guide answer](README.md#92-what-is-the-aba-problem)

ABA occurs when a thread reads A, pauses, then sees A again and assumes nothing changed. Another thread may have changed A→B→A in the meantime. A value-only CAS succeeds because the current bits equal A, even when the intervening history matters to correctness.

```text
Thread 1: read A ---------------- CAS(expected A) succeeds
Thread 2:          CAS A→B; then CAS B→A
```

ABA matters when related state, node ownership, or lifetime changed during the pause—not for every CAS algorithm.

```mermaid
sequenceDiagram
    participant T1 as Thread 1
    participant T2 as Thread 2
    T1->>T1: Read A
    T2->>T2: Change A to B
    T2->>T2: Change B back to A
    T1->>T1: CAS expects A; sees A and succeeds
```

**Architect insight /pitfall:** Equal current values do not prove an unchanged history. State the invariant first; add versioning or redesign only when intervening transitions can invalidate it.
